# tools/monitor — Single-Instance Monitor Implementation Plan

> **For Claude:** implementation via superpowers:subagent-driven-development, one task per section under "Tasks". Before writing any UI code, implementers MUST read `docs/design/monitor-mockup.html` (the user-approved visual spec — its tokens, grid template, and markup shapes are binding) and invoke the `.agents/skills` design skills (better-layout, better-typography, better-ui, better-accessibility). This plan supersedes the retired hub-view approach: the monitor is a standalone app for ONE harness serve instance.

**Goal:** a build-free, dependency-free vanilla JS/HTML/CSS app (`tools/monitor/index.html`) that answers "what is this instance doing right now" (board), lets the operator open any session's full history with a live tail (detail), and speak into it (composer → `prompt_async`). Light-first with a dark variant, both driven by one token set.

**What it talks to (no server changes):** `GET /health` (identity: version, session_sync, started_at — unauthenticated), `GET /session` + `GET /session/{id}` (composite state), `GET /session/{id}/message` (durable history), `GET /event?from=<seq>` (fetch-streamed SSE; resume cursor primed from the first poll, hub-style, to avoid full-journal replay), `GET /session/{id}/queue` (pending + watermark), `POST /session/{id}/prompt_async` (composer). Auth is `Authorization: Bearer` only — hand-rolled SSE-over-fetch, never `EventSource` (can't set headers). The box must run with `-cors-origin` covering the monitor's origin, as with the other tools.

**House patterns (both existing apps establish these — follow exactly):**
- Single `index.html`; pure helpers inside `/* TESTABLE-BEGIN */ … /* TESTABLE-END */`; `monitor_test.mjs` extracts that region and `vm`-evaluates it (copy the extraction preamble from `tools/inspector/inspector_test.mjs`).
- The SSE frame parser: reuse the established `createSSEParser` implementation (copy from inspector — this is the accepted duplication pattern between these tools).
- Token storage: `localStorage` with the inspector's documented plaintext-tradeoff comment; box base URL + route in the URL fragment (`#b=<base>&s=<session id>` — small explicit params, not the hub's base64 blob; codec is a tested pure helper).

## Pure helpers (the tested core — all inside TESTABLE)

1. `createSSEParser` (copied), `maxSeq` (copied where applicable).
2. `reduceActivity(prev, ev)` — the fold from the architecture: phases `idle | streaming | tool | between`, current tool `{name, sinceAt}`, turn accumulation `{startedAt, toolCalls}`, `lastEventAt`, `lastOutcome`. Seeded from poll data for sessions already mid-turn at connect (running ⇒ open turn, unknown start ⇒ elapsed renders `—`, never fabricated).
3. `staleness(activity, nowMs)` → `live | quiet | stalled` with exported `QUIET_MS = 15000`, `STALL_MS = 60000`. Idle is never quiet/stalled.
4. `boardModel(sessions, activities, now)` — merges poll + derived state into render-ready rows: phase word, detail cell (tool cmd | idle outcome | parked), non-zero queue counts only, goal line presence, sort (active first, then by recency).
5. `transcriptModel(messages, liveEvents)` — folds durable messages plus live deltas/tool events into render items: operator/assistant/tool entries, tool folds pairing `tool.start`/`tool.end` (unpaired start = running fold, open, with streaming output), turn markers, and the streaming caret position. Sent-composer messages appear as operator entries the moment the corresponding `prompt.queued`/`message` event arrives on the stream — the stream is the single source of transcript truth (no client-side phantom entries).
6. `fmtElapsed(s)` / `fmtAgo(ms)` (mockup's formats), `route`/`unroute` fragment codec.

Every helper gets `monitor_test.mjs` coverage; the reducer and transcript fold get the awkward cases: mid-turn connect, tool.end without start, deltas during an open tool fold, out-of-order seeding, turn markers across busy/idle transitions.

## Views (per the mockup, binding)

- **Board:** shared grid template (`--col-dot 8px · --col-phase 84px · content · elapsed`, one gap token); header flush-left with identity line from `/health` + connection state in the elapsed column; session rows one line (+ optional second line for goal/stall note, placed in the content grid column); full session ids, ellipsize only under real width pressure; idle group separated by a larger gap; legend footer. 1s ticker updates elapsed/staleness text only.
- **Detail:** breadcrumb back; header (full id, msgs/turn/tool-call counts, live chip); transcript as typographic document (speaker rail on the 84px column, 70ch body); tool folds (`<details>`, completed collapsed with cmd + elapsed, running open with tailing output + reduced-motion-respecting caret); sticky composer (the app's only filled-accent control; Enter sends, Shift+Enter newline; `field-sizing: content` with fallback rows behavior). Composer failures (non-2xx) surface inline under the input in critical color with the server's error text — no toasts.
- **Connection lifecycle:** initial `/health` + `/session` poll → prime `from` cursor → open stream; jittered-backoff reconnect resuming from last seq; 5s poll refreshes composite/queue fields the stream doesn't carry. Stream status shown honestly in the header (streaming / reconnecting / disconnected).
