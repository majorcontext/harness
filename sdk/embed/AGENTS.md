# sdk/embed

Read the root AGENTS.md and `sdk/AGENTS.md`. The rules of `sdk/typescript` do not bind this package.

- This package is the page-side client of the WebAssembly module (`docs/architecture.md`, `Public packages`; the module is in `WebAssembly`). It speaks ACP to the module and has no UI and no ACP client of its own.
- Keep it plain ESM that runs in a browser, a Worker, and Node. Import a Node built-in only by a dynamic `import()` behind a Node check, so a browser bundle never loads it.
- Add no runtime dependency without a design decision. A dependency or a build step needs the same decision.
- The message names between the page and the Worker are the contract of `src/bridge.mjs` and `src/workerbridge.mjs`. Change both ends together.
- A new option of `createHarness` needs a line in the Public packages section of the spec first.
- A message to the Worker moves data, not functions. Keep every option serializable.
- Tests start the real module in a Worker against a scripted model server. The model is `internal/embedfake`, the scripted server of `harnesstest`; a test double of its own would escape the wire gate. The tests need `HARNESS_WASM`, `HARNESS_WASM_EXEC`, `HARNESS_EMBEDFAKE`, and `HARNESS_BIN` (the built `cmd/harness`), and a missing variable fails the test. `test/suite.mjs` holds the client API tests that both transports pass; `embed.test.mjs` runs it over wasm and `subprocess.test.mjs` over the native binary.
- A transport declares what it supports (`supports`, `defaultTools`, `start`). `createHarness` never branches on `transport.kind`; a new option goes in `supports` of every transport.
- Keep `src/index.d.ts` equal to the exported API of `src/index.mjs`.
- The browser job is the exception: `e2e/browser_test.go` serves the `harnesstest` Anthropic server in the Go test process behind a CORS wrapper, because the rows need `AwaitCanceled`.
- Run `node --test sdk/embed/test/*.test.mjs`.
- `test/browser.mjs`, `test/browser-host.mjs`, `test/browser-server.mjs`, and `test/browser/page.mjs` are the fixture of `e2e/browser_test.go` and `e2e/acp_browser_test.go` (headless Chromium). The ACP rows share one Chromium (`browser-server.mjs`), and each row works in a browser context of its own. Run it with `npm ci` in this directory, `npx playwright install chromium`, and `HARNESS_E2E_BROWSER=1 go test -race ./e2e/ -run 'TestBrowserRows|TestACPBrowserScenarios'`. `playwright` is a dev dependency, pinned in `package.json` and the lock file; the package has no runtime dependency.
- `test/browser/soak.mjs` is the soak row (`e2e/browser_soak_test.go`, `HARNESS_E2E_SOAK=1`, the scheduled `browser-soak.yml` job). It reads the memory of the module through a probe that the test appends to `wasm_exec.js`, so the Worker needs no test code.
- Only the Worker of a browser and the in-process mode (`src/inprocess.mjs`, `worker: false`) load `src/opfsfs.mjs`; only the Worker of a browser loads `src/browserfs.mjs`. The in-process mode replaces `globalThis.fs`, `process`, and `path`, so `wasm.mjs` refuses it under Node. `src/memoryfs.mjs` is its public export. `test/workerd/` is the fixture of `e2e/workerd_test.go` (`HARNESS_E2E_WORKERD=1`, the `workerd` package of the lock file); it bundles the Worker with esbuild.
- `browserfs.mjs` and `opfsfs.mjs` set `globalThis.fs`, `process`, and `path` before `wasm_exec.js` runs, and the store Web Lock comes before any file opens. `opfsfs.mjs` implements the calls of `syscall/fs_js.go` and `wasm_exec.js` and nothing else; a call that Go gains in a new Go version needs a line in `e2e/testdata/fsprobe` first. Every callback answers once with `null` or an error whose code is in Go's table (`syscall/tables_js.go`): an unknown code panics Go. Change the lock, the open order, and `docs/architecture.md` (Store) together.
- `test/storelock.test.mjs` needs no module build. The rest of the tests in `test/*.test.mjs` need the variables above.
- `src/shell.mjs` and `src/shellfs.mjs` are the optional `shell` export. Import nothing of just-bash in `src/index.mjs`, `bridge.mjs`, or `wasm.mjs`: a page that does not import the export loads nothing extra. The shell never gets a `network` option of just-bash. `h.fs` exists in a browser only, because the module under Node runs on the real disk. `test/browser.mjs` bundles `just-bash/browser` with esbuild (both are dev dependencies) and serves it to the page at `/vendor/just-bash.js`.
