# Changelog

Harness is a fast, extensible, composable agent harness in Go. It ships a headless engine library, a CLI, and an HTTP+SSE server.

Harness is pre-1.0. The engine API, config schema, and plugin protocol may change between minor versions.

## v0.1.0 — Unreleased

First tagged release.

### Added

- **Engine library** (`engine`) — sessions are append-only logs of canonical messages. A session can change provider or model between turns with no history migration. Persisted sessions resume by ID.
- **Providers** (`provider/...`) — Anthropic Messages, OpenAI Responses, any OpenAI-compatible chat-completions endpoint (OpenRouter, Ollama, vLLM), and delegated turns through the Claude Code CLI.
- **CLI** (`cmd/harness`) — `harness run` for one-shot prompts, `-goal` for evaluator-checked goals, `harness serve` for the HTTP+SSE session API, and `harness sessions` to list saved sessions.
- **Tools** — built-in file and shell tools, custom Go tools through `engine.Config.Tools`, subagents through the `task` tool, and managed long-running processes (`process`).
- **Plugins** (`plugin`, `sdk/typescript`) — a language-neutral process protocol with a Go SDK and a TypeScript SDK.
- **MCP** (`mcp`, `mcpserver`) — an MCP client with deferred tool loading, and a Streamable HTTP MCP server. `mcpserver.CallMeta` gives a tool handler the `_meta` object of its `tools/call` request.
- **Context management** — automatic and manual compaction, project `AGENTS.md` instructions, and [Agent Skills](https://agentskills.io/specification) (`skill`).
- **Deferred goals** — `POST /session/{id}/goal` accepts `defer: true` to arm a goal without posting its condition as a standalone turn. The loop starts after the next prompt turn and evaluates that turn first; on NOT MET the guidance turn carries the condition. `max_turns` caps the auto-armed loop, for deferred goals and for goals armed behind a busy prompt. A goal loop that spends `max_turns` without a MET verdict ends the goal: it journals `goal.cleared` with `goal_reason` `goal exhausted max_turns (N)` before `turn.end` with outcome `max_turns_exceeded`, and the session reads `idle`. On an idle session, updating an armed goal keeps it armed with the new condition and answers `armed`. A `max_turns` above 0 replaces the cap; omitted or 0 keeps it. Behind a busy prompt, the update answers `updated` and keeps `max_turns`. No evaluation runs until a turn finishes.
- **Context-window refresh** (`modelmeta`) — `go generate` rewrites the context-window tables from models.dev, and a daily workflow opens a pull request when they change. A new point release is recognized without a hand edit. Session creation still makes no network call.
- **Test model server** (`harnesstest`) — a scripted model server for tests in other modules. `New` speaks the Anthropic Messages wire; `NewChat` speaks the OpenAI chat-completions wire, with `Reply.Reasoning` and `Reply.ErrorCode`, and fails the test on a request that a real gateway rejects. Steps match requests in declaration order, `Block` steps wait for `Release`, `AwaitCanceled` observes a client that dropped a blocked request, replies can carry an error message and a `Retry-After` header, and the server fails the test on an unmatched request or a step that never matched.
- **Event-sink test receiver** (`harnesstest`) — `NewSinkReceiver` starts a scripted event-sink receiver that records every batch as a `SinkBatch`, answers each one through a `SinkReply`, and lets a test wait on the received batches with `Await`.
- **Session runtime core** (`harness`, `protocol`) — `harness.New` returns a `Runtime` that runs each session as one actor goroutine over a `Store`. `Create`, `Open`, `List`, and `Close` manage sessions; `Session` has `View`, `Submit` (idempotent by client input ID), `Interrupt`, `Events` (durable events after a seq, then live ones), and `Release`. An `Owner` grants each session; `Open` appends `owner.acquired` to fence earlier owners, ends a crashed turn and starts the next queued input on the same `Open`, and resumes a turn that a handoff suspended. `OpenView` reads a session without owning it.
- **Session replication** (`harness`, `protocol`) — `Options.Sync` receives every record that a `Runtime` appends, in seq order, as a `protocol.SyncBatch`. A batch carries the blob of each `backend.state` record in it. A failed delivery resends the same batch; a `SyncAck` below the batch makes the sender resend from `Head+1` out of its `Store`. `ErrStaleEpoch` stops the session without another append. `Session.Release` and `Runtime.Close` return after the last record is acknowledged, and `Session.View` reports `SyncedSeq`. `ApplySync` implements the receiver rules over any `Store` for an embedder.
- **Codex backend** (`harness`) — `Options.Config` configures model providers, and the `provider/model` ref of `CreateSession` selects one. A `type: openai` provider runs turns on the OpenAI Responses API, the ChatGPT Codex lane included, over HTTP or the websocket transport. `Options.ModelTransport` supplies the HTTP transport of each provider, for each HTTP request and each websocket dial. The transport may supply the credentials, so the key variable may be unset. A model that no configured provider serves, or that `modelmeta` does not know, fails `Create` with `ErrModelUnavailable`; `context_window_required: false` or `context_window_tokens` allows an unknown model, and a ref with no provider fails with `ErrInvalidRequest`. A retryable model error, or a response with no text and no tool call, runs the turn again with backoff, up to `prompt_retries` times, when the turn has recorded no item. `Runtime.Close` closes the pooled websocket connections, also after a timed-out close. A reasoning item replays with its provider data. The model sees the session history from the newest compaction summary on.
- **Model API backends** (`harness`, `harnesstest`) — a `type: openai-compat` provider, such as Bifrost, and the `anthropic` provider with no type run `Runtime` turns on the chat-completions and Anthropic Messages wires, through the one backend that also runs `type: openai`. `Options.ModelTransport` supplies the HTTP transport of each, and may supply the credentials, so the key variable may be unset. Each request sends a baseline response cap of 8192 tokens, which a reasoning request can raise. A response with no text and no tool call fails as `modelapi: the response has no output`. `harnesstest.Request.MaxTokens` reports the cap that a request sends, on each wire.
- **Embedder tools** (`harness`, `protocol`) — `Options.Tools` takes `Tool` values that the model can call. After a model call that asks for tools, the turn runs each call in order, records its result, and calls the model again, until a call asks for no tool. A tool error, or a call to a tool that the session does not allow, is an error result that the model sees. `CreateSession.AllowedTools` restricts the tools that the model sees and may call; nil allows every tool. An interrupt stops a running tool, and the call gets an interrupted result. A handoff lets a running tool finish and starts no new tool. `ToolCall.ID` is the model's call ID.
- **Claude Code backend** (`harness`) — a `type: claude-code-cli` provider runs each turn of a `Runtime` session as one `--resume` run of the Claude Code CLI over stream-json. The CLI runs its own tools and compacts its own context. Its messages are recorded as items, its compaction as `compaction.applied` with `by_backend`, and its usage and context window as turn usage and `context.measured`. A `steer` input reaches the CLI on stdin while a tool runs. `Session.Interrupt` and a handoff send SIGINT to the process group of the CLI. Every item that the CLI wrote before it exits is recorded, and a tool call with no result gets an interrupted result, or a cut-off result before `turn.suspended` on a handoff. A stopped turn whose CLI still writes a success result completes. A stopped turn whose CLI exits with no result ends with the stop, never as a retryable failure. A turn that resumes after a handoff, or runs again after a retryable failure, sends a fixed continuation message instead of its input when the resumed CLI session already holds that input. The message says that the previous turn was interrupted, and names no cause. The external session ID is saved as a `backend.state` blob, one blob for each owner, and with `session_mirror: true` the blob also holds the transcript that `--session-mirror` reports, so a session opened on another runtime resumes it. A mirrored session with no saved transcript starts a new CLI session. Embedder tools reach the CLI through a loopback MCP server named `harness` that each turn serves while it runs, given to the CLI with `--mcp-config` and allowed with `--allowedTools mcp__harness`. A call runs `Tool.Run` with the CLI tool use ID as `ToolCall.ID`, and a call with no tool use ID is an error result. Items record the call by the embedder tool name. A call that an interrupt or a handoff stops gets no reply, so it gets an interrupted or cut-off result. `CreateSession.AllowedTools` names built-in tools of the CLI and embedder tools. The built-in names map to `--tools` with `--strict-mcp-config`, and the MCP server offers only the allowed embedder tools and the allowed tools of `Config.MCPServers`. An unrestricted session gives each server of `Config.MCPServers` to the CLI in the same `--mcp-config` file, by its config name, as the engine does: a stdio server as `command`, `args`, and `env`, an HTTP server as `type: http`, `url`, and `headers`. The CLI connects them itself, the runtime does not, and `--strict-mcp-config` hides every other MCP config of the CLI. Any other name fails `Create` with `ErrInvalidRequest`, and so does an embedder tool with the name of a built-in tool of the CLI. An init frame that shows another tool fails the turn.
- **Live frames** (`harness`, `protocol`) — `Session.Events` also yields the ephemeral frames of a running turn to a live reader: `item.started` and `item.delta` (`protocol.ItemFrame`) for the text and reasoning deltas of the Codex backend, and `status` (`protocol.StatusFrame`) while a turn waits to retry. The Claude Code backend sends each finished text or reasoning block as one delta. An item that a failed attempt started never completes, and the next attempt starts a new item. The store never holds them. Each frame has `Ephemeral` set and the last durable seq, and its `item_id` is the `item_id` of the `item.completed` record that ends the item. A reader that resumes after a seq gets the durable events of the gap, then live frames. A slow reader can miss any frame, never a durable event, so the deltas of an item can have holes; its `item.completed` holds the whole item. `View.Events` yields durable events only.
- **Model list** (`harness`, `modelmeta`, `protocol`) — `Runtime.Models` returns the models that the configured providers serve, sorted by ID, each with its provider and context window (0 when the backend reports it during a turn, as Claude Code does). It does no I/O. `modelmeta.Models` lists the models of a provider: the ChatGPT subscription models for `codex` and the CLI aliases for `claude-code`. Other providers list no models.
- **Session settings** (`harness`, `protocol`) — `Session.Update` takes a `protocol.SettingsPatch` that changes the model, the effort, or the service tier, appends `settings.changed` for the values that differ, and returns the view. The next turn uses the new settings; a running turn keeps its own. A model that no configured provider serves, or that `modelmeta` does not know, fails with `ErrModelUnavailable`, and an unknown effort with `ErrInvalidRequest`. A session can move between Responses providers, such as `codex` and `openai`, and the next provider gets the whole history. A move to or from a provider whose backend owns its context, such as `claude-code`, fails with `ErrInvalidRequest`; a move between the models of one such provider is allowed. A turn that a handoff resumes uses the settings at its resume. A backend that has no service tier ignores it.
- **HTTP API** (`harness`, `protocol`) — `Runtime.Handler` serves the session API over HTTP: `POST /sessions`, `GET /sessions?after=&limit=`, `GET` and `PATCH /sessions/{id}`, `POST /sessions/{id}/inputs`, `POST /sessions/{id}/interrupt`, `GET /sessions/{id}/events`, `GET /models`, and `GET /health`. A route that names a session opens it through `Runtime.Open`. A new input answers 201 and a repeat of its ID answers 200 with the original receipt; `Session.Admit` is `Submit` with that verdict. An `Accept` header selects SSE only when it lists `text/event-stream` with a quality above 0. `GET /sessions/{id}/events?after=&limit=` returns a `protocol.EventPage` of durable events; with `Accept: text/event-stream` it streams the durable events after `after`, or after `Last-Event-ID` when it is set, then the live ones with the ephemeral frames between them. A durable frame carries its seq as the SSE id, and an ephemeral frame has no id. An error is a `protocol.ErrorBody` with a code from the `protocol.Code` constants, mapped from the sentinel errors; an unmapped error is `internal` with a fixed message, and a path or method that no route serves answers 404 or 405 with `invalid_request`. A body above 8 MiB fails with `payload_too_large`. The handler has no authentication; the embedder wraps it.
- **Runtime compaction** (`harness`, `protocol`) — `Session.Compact` and `POST /sessions/{id}/compact` fold the turns before the newest `compaction_keep_turns` (default 2) into a summary that the session model writes with the compaction prompt of the engine, and append `compaction.applied` with `by_backend: false`. The next model call reads the summary first. A session with too few turns appends nothing. A Claude Code session runs `/compact` as a turn of the CLI, which logs `compaction.applied` with `by_backend: true`. `Compact` returns when the compaction ends, and fails with `ErrSessionBusy` (`session_busy`, 409) while a turn runs or inputs wait. Before a queued input starts a turn, a session whose newest `context.measured` reading is at or above `compaction_threshold` (default 0.8) of its window compacts first. A failed summary appends nothing, and the turn starts on the full history. A handoff stops a running compaction, and the next owner runs the input that waited for it. `Open` starts the next queued input when no turn is open. The Codex backend records the prompt size of each model call that reports prompt tokens, and the model window, as `context.measured`. A `compaction_threshold` or `compaction_keep_turns` at or below 0 is the default.
- **System prompt** (`harness`) — `Options.WorkDir` names the directory of a coding agent. Each session reads its system prompt once, when it is created or opened: the base prompt, `append_system_prompt`, the `AGENTS.md` chain from the git root down to `WorkDir` cut at `instructions_max_bytes` (default 64 KiB; a negative value keeps the whole file) with a marker, and the skill list. A file that cannot be used is skipped with a WARN log line. With no `WorkDir`, the prompt is `append_system_prompt` alone and no file is read. The log never holds the prompt. A Claude Code session gets `append_system_prompt` as one `--append-system-prompt` value, and the CLI runs in `WorkDir`.
- **Processes** (`harness`) — with `Options.WorkDir`, the runtime runs `Config.Processes` through the `process` tool: `start`, `stop`, `restart`, `status`, `logs`, `list`, `declare`, and `undeclare`. Each turn sends a status line inside `<harness-engine-context>` tags after the system prompt that names each started process, its state, its ports, the instant of its last change, and its log path. `Runtime.Close` stops every process, also when its ctx ends first. With no `WorkDir`, no process runs and the model sees no `process` tool. `declare` runs any argv, so a `WorkDir` grants command execution.
- **MCP tools** (`harness`) — a `Runtime` session gets the tools of `Config.MCPServers` as `mcp__<server>__<tool>`. The first model call of a turn that the runtime serves the MCP tools for connects every server once for each runtime; an unrestricted Claude Code turn connects none, because the CLI does. A server that fails stays down until the model calls `mcp(action="connect")`. With `mcp_tool_loading` `lazy`, or `auto` over `mcp_tool_loading_threshold` (default 20) tools, or a server `tool_loading` of `lazy`, the system prompt lists the deferred tools, and the model loads one with `mcp(action="select")` or finds one with `mcp(action="search")`. A loaded tool is callable on the next request of the turn, and a call of a deferred tool runs it. The history decides which tools are loaded, so a replay loads the same tools. The instructions of the servers that the first connect reached join the system prompt in `<mcp_instructions>`. A server that serves resources adds `list_mcp_resources` and `read_mcp_resource`. A result is text: a binary item becomes one line with its size and type, and an error that is not the server's own RPC error never names the endpoint URL or a response body. `Runtime.Close` closes every connection. With `mcp_servers`, an embedder tool with an MCP tool name fails `New`. The base prompt of a `Runtime` session says that the harness appends the process status to the system prompt.
- **Model call recovery** (`harness`) — a `Runtime` session recovers from a failed model call by its class. A context overflow compacts the session while the turn runs and calls the model again; when no turn can fold, the turn fails. A provider usage limit, such as a spent quota, ends the turn `failed` with cause `provider_exhausted`. A model call that reports no wire activity for `stream_idle_timeout_s` (default 300; a negative value turns it off) stops and runs again as a retryable error; tool arguments that still stream count as activity. A response cut off at `max_tokens` runs none of its tool calls, which get an error result, and the next call asks the model to continue, up to `max_tokens_continuations` times in the turn; past that the turn fails, and 0 or less ends the turn at the cut. The continuation message is not logged. Any other error fails the turn. A Claude Code session has no stall limit.
- **Goals** (`harness`, `protocol`) — `Session.SetGoal` and `Session.ClearGoal`, and `PUT` and `DELETE /sessions/{id}/goal`, run a `Runtime` session goal as Claude Code `/goal` does. On a session with no running turn and no queued input, the condition is the input of the first turn, with `source: goal`; otherwise the next turn that ends is the first one judged. `SetGoal` needs `goal_evaluator_model`. After each turn that completes or is interrupted, that model judges the history; a reply that starts with markdown marks still counts, and an interrupt during the judgment stops nothing. The verdict: `met` achieves the goal, `impossible` fails it, and `not_met` admits its guidance as the next input until `max_turns` (0 is unlimited) exhausts the goal. A retryable error or a usage limit pauses the goal, which runs again after a backoff from 30 s to 30 min, or at the next input; any other error fails it. A verdict, a pause, or a failure withdraws the queued goal input. `ClearGoal` stops a goal turn with cause `goal_cleared`. A goal has one retry timer, and any change of the goal stops it. `ClearGoal` starts an input that a paused goal left queued. `Open` judges the last turn of an active goal and keeps the retry time of a paused goal. `protocol.Session.Goal` reports the condition, state, judged turns, reason, and retry time. There is no deferred goal.
- **Plugins** (`harness`) — a `Runtime` session gets the tools and hooks of `Config.Plugins`. The first `Create` or `Open` of a runtime reads the manifest of each plugin with one probe, bounded at 30 s. A probe that fails, a manifest of another name, or a plugin tool with the name of another tool or of a built-in tool of the model backend fails that call, and the next call tries again; a call after `Close` returns `ErrDraining`. A plugin process starts on its first hook or tool call. `tool.execute.before` can rewrite or deny each tool call, and `tool.execute.after` can rewrite its result, also for a call that a backend that owns the loop makes. The `system.transform` segments of each model call, which get the model of the call, follow the MCP segment. The `event` hook gets `session.status` and `session.error` from the appended turn records, `tool.execute.start` and `tool.execute.end` around each call that runs, and `file.edited`, with an absolute path, after a `write_file` or `edit_file` call that succeeds. `client/session.messages` reads the session from the store. The runtime does not dispatch `chat.params`, `chat.message`, or `shell.env`, and fails `client/mcp.call`. `Runtime.Close` stops every plugin process.
- **Config rules** (`config`) — `Config.Validate` is the one rule set for a hand-built or loaded `Config`, and never changes it. `Defaults` returns the built-in value of every defaulted key. `Config.ApplyEnv` sets each top-level string, number, or bool key from a non-empty `HARNESS_<KEY>` variable, and a parse error names the variable but not the value. `ProcessSpec.Validate` is the process entry rule that `process.Declare` also uses. The package imports only the standard library.
- **Documentation** — package docs on pkg.go.dev, `engine` examples, and runnable programs in [`examples/`](examples).
- **Claude Code structured questions** — `harness serve -ask-user-question` lets a Claude Code session ask the user an `AskUserQuestion` question. The turn ends with outcome `awaiting_input` and a `question_call_id`, and `POST /session/{id}/question/{call_id}/answer` resumes it. Off by default.
- **Children** (`harness`, `config`) — with a `WorkDir`, each `Runtime` session has a `task` tool, `{agent, prompt}`, that starts a child session in the background and returns its ID at once. The child is a session with `parent_id`; its first turn runs the prompt. When a turn of the child ends, the parent records `child.settled` and gets a report input with `source: child`: the outcome (`done`, `failed`, or `canceled`), the error, and the last assistant text of the child. A parent that opens after a crash settles each child that ended and opens each child that did not. Agent profiles load from `<workdir>/.agents/*.md` in the agent format of Claude Code (`name`, `description`, `tools`, `model`, and a prompt body) beside the built-in `general-purpose`, `explore`, and `plan`, and set the allowed tools, model, and prompt of the child. `explore` and `plan` allow only the read-only file tools. `max_task_depth` (default 3) and `max_concurrent_tasks` (default 20) bound each session tree.

### Changed

- **Model resolution** (`config`) — `Config.ResolveModel` returns the resolved ref string and does not parse it. A caller parses it with `message.ParseModelRef`.
- **Runtime config check** (`harness`) — `harness.New` returns `ErrInvalidRequest` for an `Options.Config` that fails `Config.Validate`, so a bad provider, plugin, MCP server, or process entry fails at `New`, not at the first model call or process start.
- **Credentials from the HTTP client** (`provider/anthropic`, `provider/openaicompat`) — a `Client` with an `HTTPClient` and no `APIKey` sends no key header, so the client can supply the credentials, as `provider/openai` does. A `Client` with neither still fails with `no API key configured`.
