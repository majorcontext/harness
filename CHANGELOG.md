# Changelog

Harness is a fast, extensible, composable agent harness in Go. It ships a headless runtime library, a CLI, and an HTTP+SSE server.

Harness is pre-1.0. The runtime API, config schema, and plugin protocol may change between minor versions.

## v0.1.0 — Unreleased

First tagged release.

### Added

- **Sessions** (`harness`) — sessions are append-only logs of canonical messages. A session can change provider or model between turns with no history migration. Persisted sessions resume by ID.
- **Providers** (`internal/provider/...`) — Anthropic Messages, OpenAI Responses, any OpenAI-compatible chat-completions endpoint (OpenRouter, Ollama, vLLM), and delegated turns through the Claude Code CLI.
- **CLI** (`cmd/harness`) — `harness run` for one-shot prompts, `-goal` for evaluator-checked goals, `harness serve` for the HTTP+SSE session API, and `harness sessions` to list saved sessions.
- **Tools** — built-in file and shell tools, custom Go tools through `Options.Tools`, subagents through the `task` tool, and managed long-running processes (`process`).
- **Plugins** (`internal/plugin`, `sdk/typescript`) — a language-neutral process protocol with a published TypeScript SDK (the Go SDK is internal to the harness module).
- **MCP** (`internal/mcp`) — an MCP client with deferred tool loading, and a Streamable HTTP MCP server (`mcp.Registry`). `mcp.CallMeta` gives a tool handler the `_meta` object of its `tools/call` request.
- **Context management** — automatic and manual compaction, project `AGENTS.md` instructions, and [Agent Skills](https://agentskills.io/specification) (`internal/skill`).
- **Context-window refresh** (`internal/modelmeta`) — `go generate` rewrites the context-window tables from models.dev, and a daily workflow opens a pull request when they change. A new point release is recognized without a hand edit. Session creation still makes no network call.
- **Test model server** (`harnesstest`) — a scripted model server for tests in other modules. `New` speaks the Anthropic Messages wire; `NewChat` speaks the OpenAI chat-completions wire, with `Reply.Reasoning` and `Reply.ErrorCode`, and fails the test on a request that a real gateway rejects. The Anthropic double also fails the test on a `tool_result` block that does not follow its `tool_use` or that repeats one, and `Request.CacheBreakpoints` lists the `cache_control` markers of an Anthropic request. Steps match requests in declaration order, `Block` steps wait for `Release`, `AwaitCanceled` observes a client that dropped a blocked request, replies can carry an error message and a `Retry-After` header, and the server fails the test on an unmatched request or a step that never matched.
- **Session runtime core** (`harness`, `protocol`) — `harness.New` returns a `Runtime` that runs each session as one actor goroutine over a `Store`. `Create`, `Open`, `List`, and `Close` manage sessions; `Session` has `View`, `Submit` (idempotent by client input ID), `Interrupt`, `Events` (durable events after a seq, then live ones), and `Release`. An `Owner` grants each session; `Open` appends `owner.acquired` to fence earlier owners, ends a crashed turn and starts the next queued input on the same `Open`, and resumes a turn that a handoff suspended. `OpenView` reads a session without owning it. `DiskStore` fences each append with a `flock` of the session log, so a stale `DiskStore` instance on the same root, in any process, gets `ErrConflict`. `storetest.RunInstances` takes an opener of instances over one storage and checks that fence across instances. A `DiskStore` reader takes a shared lock, so it never scans bytes that a failed append cuts again, and a wait for a lock ends with the context of the call. A `DiskStore` keeps a sparse index of line offsets in memory and reads from the nearest indexed line, so a tail `Read` does not scan the log from its first line.
- **Session replication** (`harness`, `protocol`) — `Options.Sync` receives every record that a `Runtime` appends, in seq order, as a `protocol.SyncBatch`. A batch carries the blob of each `backend.state` record in it. A failed delivery resends the same batch; a `SyncAck` below the batch makes the sender resend from `Head+1` out of its `Store`. `ErrStaleEpoch`, or an `ErrConflict` for records that differ from the receiver's, stops the session without another append and releases its ownership; `Session.Release` returns the `ErrConflict` rejection. `Session.Release` and `Runtime.Close` return after the last record is acknowledged, and `Session.View` reports `SyncedSeq`. `ApplySync` implements the receiver rules over any `Store` for an embedder.
- **Events after a cursor** (`harness`) — `harness.ReadEvents(ctx, store, id, after)` yields the stored events after a seq, through the head it reads first, with no ownership, no append, and no replay. On a log that replays it equals `View.Events`. A record whose envelope seq differs from its store seq ends the sequence with `ErrSeq`.
- **Sync from a box** (`harness`, `config`) — the config keys `owner_epoch` and `sync {url, token_file}` make `harness.New` grant each session at that epoch and post every `protocol.SyncBatch` to `sync.url` with the bearer token that it reads from `token_file`. The receiver contract maps `409 stale_epoch` to `ErrStaleEpoch`, `409 sync_conflict` to `ErrConflict`, `400 invalid_request` to `ErrInvalidRequest`, and `413 too_large`, `401`, and `403` to `ErrSyncRejected`; each ends the session, and a `5xx` or transport error resends. A batch stays under 32 MiB. `Runtime.CatchUp` replicates every stored session without opening it: `Open` of a session that it holds ends its catch-up, `Close` ends it with `ErrDraining`, and an unreadable session is skipped and reported. `Options.ServeURL` and `Options.RunToken` give a plugin `serve_url` and `run_token`.
- **Mid-turn delivery** (`harness`, `protocol`) — an input with no `delivery` is `steer`: a prompt sent while a turn runs joins that turn at its next item boundary, on a model API backend and on Claude Code. A child report joins a running parent the same way on a model API backend, and the model reads it in the `[tasks: …]` segment of the engine, and not under the `OPERATOR MESSAGES` heading. The segment is pinned: the model reads it at the same place in each later model call, and no history that a reader sees holds it. A compaction moves a segment that it keeps to the end of the kept history, as the engine did; it moves a segment that it folds to the end of the history, so a tool call stays with its result; and a restart keeps the segment, which the engine lost. On Claude Code a child report to a busy parent is not injected in the middle of the turn: the next turn that starts reads every waiting report. A turn that a prompt starts reads the reports in the segment after the text of the prompt, after a blank line, as the engine did; a turn that only reports start reads the trigger sentence of the engine and then the segment, so the result of a child reaches the model once. The report of a child has the text of the engine: a failed child reads the classified reason, a child that a usage limit or a rate limit stopped adds the guidance not to spawn a replacement, a crashed child reads `lost to restart: turn was in flight when the process last stopped`, the cause is masked and cut at 500 runes and the recover hint at 120, and a result of at most 4096 bytes stays whole while a larger one shows a 4096-byte preview with a `read_tool_result` handle. `turn.ended` carries `error_class`, `recover_hint`, and `error_detail` for that text. The `status` and `log` actions of the `task` tool show the same reason for a failed child. An internal goal input and `/compact` stay `queue`.
- **Input provenance** (`harness`, `protocol`) — `protocol.Input` takes `source_id` (at most 128 printable ASCII bytes) and `source_label` (valid UTF-8, cut at 256 bytes, with control, bidi, and zero-width characters dropped, as the engine did); a bad `source_id` is `invalid_request` and leaves no trace, also on a typed slash command. A prompt command keeps the `source_id` and takes the typed line as `source_label`, with `source` `command`. `input.admitted` records both, and a repeat that differs in either is `input_conflict`. A user message of `protocol.MessagePage` carries `source`, `source_id`, and `source_label` of the input that started its turn, also for an input that the runtime admits itself (`parent`, `child`, `goal`, `harness`). A user message that joined steer inputs carries `operator_batch`, one entry of `id`, `text`, `source`, `source_id`, and `source_label` for each input.
- **Message time** (`protocol`) — a message of `protocol.MessagePage` carries `created_at`, the envelope time of the record that completed it, as the engine stamped `CreatedAt`. A reader shows it as the time of a message in history and on a live message.
- **Claude Code state chunks** (`harness`) — a Claude Code session saves its state as a chain of `backend.state` records, not as one blob that grows. Each record carries the head (the CLI session ID, turn, parked call, and transcript path). The transcript entries are appended as chunk blobs of whole entries, at most 4 MiB each (an entry over 4 MiB is a chunk of its own), and each chunk has its own record, so a `SyncBatch` never carries the whole transcript again and a long session no longer reaches the 32 MiB bound of a batch. A chunk key holds the backend, the fence of the owner, and an index, so a fenced owner never overwrites the chunk of another owner. A save whose entries do not extend the chain, such as a new CLI session, starts a new chain and keeps none of the old entries. A record of the older form (`blob_key` alone) still reads, as a chain of one blob, and the next save starts a new chain. `turn.Sink.State` and `SaveState` take and return a `turn.Snapshot` of a head and entries.
- **Read-only handler** (`harness`, `protocol`) — `harness.ReadHandler(store, queue)` returns an `http.Handler` for `GET /sessions`, `GET /sessions/{id}`, `GET /sessions/{id}/inputs`, `GET /sessions/{id}/messages`, `GET /sessions/{id}/events` (the page, and an SSE stream of the durable events that ends at the head), and `GET /sessions/{id}/blobs/{key}`. It needs no `Runtime` and no owner, appends nothing, and starts no turn. Bodies, limits, paging, SSE ids, and error bodies are those of `Runtime.Handler` for a session that the runtime does not run; a session lists no plugins. A write answers 405 in the error body. `queue` is an optional `harness.Queue` with one method, `Queued(ctx, session)`, for inputs that wait outside the log: its inputs follow the queued inputs of the log in `GET /sessions/{id}/inputs` and in `Session.queued`, and a session with no log but with waiting inputs answers `GET /sessions/{id}/inputs` from the queue alone while the other routes answer `session_not_found`. A queue error fails only the session, session list, and inputs routes. A nil `queue` lists the log only. `GET /sessions/{id}/blobs/{key}` answers the bytes of an attachment with its media type and its recorded size as `Content-Length`, on both handlers: a blob part of `protocol.MessagePage` carries `key`, and a key that no blob part of an `input.admitted` of the session names (a `backend.state` or retained tool result blob included) answers `404 blob_not_found`.
- **Spawn and open** (`harness`) — `Runtime.Create` waits for an `Open` of the same ID that is in flight and creates the session when that `Open` finds none, so an `Open` that races a spawn never fails it with `ErrSessionExists`. `harness run` opens a task child only after the log of the child holds a record.
- **Session agent** (`protocol`) — `Session.agent` is the agent profile name that a task child was spawned with. `GET /sessions` and `GET /sessions/{id}` report it. A root session has none.
- **Goal pauses** (`protocol`) — `GoalView.pauses` is the count of pauses since the last verdict. A verdict resets it to 0.
- **Goal retry budget** (`harness`) — a goal that has paused 6 times since its last verdict (about 31 minutes of backoff) and then fails again on a retryable error or a usage limit ends as `failed` with reason `retries_exhausted`, and does not pause again. This restores the retry cap of the engine, which tried 12 times and then parked. The goal stays failed; the session takes any input as usual, and a new goal starts with SetGoal.
- **End a session** (`harness`) — `Runtime.End` and `DELETE /sessions/{id}` stop a session that the runtime runs and release its ownership, with no append. A session with a running turn or control command fails with `ErrSessionBusy` (409 `session_busy`), and its descendants keep running; a running compaction or evaluation that no command started stops, as `Release` stops it. A session that is free also stops the turn of each descendant that the runtime runs, and a session that the runtime does not run is not opened for the report of a stopped child. Each such turn ends with cause `ended`; the parent settles that child with no report input. A child that a direct interrupt stops still reports `canceled`, and a tree interrupt keeps its rule: it opens the parent and settles with no report input. A session that is busy when `End` starts keeps each child report. The log stays in the store, and `Open` runs the session again. An ID with no log fails with `ErrSessionNotFound`.
- **Warm-up** (`harness`) — a session over the Codex websocket transport opens and warms its connection when it is created or woken, so the first turn chains on the warm response. The first turn waits for a warm-up that is still in flight, and never dials the connection cold. A failed warm-up costs only that speed, and a model that cannot warm costs no tool discovery or hook.
- **Codex backend** (`harness`) — `Options.Config` configures model providers, and the `provider/model` ref of `CreateSession` selects one. An empty model is `Config.Model`, or `config.DefaultModel`. A `type: openai` provider runs turns on the OpenAI Responses API, the ChatGPT Codex lane included, over HTTP or the websocket transport. `Options.ModelTransport` supplies the HTTP transport of each provider, for each HTTP request and each websocket dial. The transport may supply the credentials, so the key variable may be unset. A model that no configured provider serves fails `Create` with `ErrModelUnavailable`, and a ref with no provider fails with `ErrInvalidRequest`. A retryable model error, or a response with no text and no tool call, runs the turn again with backoff, up to `prompt_retries` times, when the turn has recorded no item. `Runtime.Close` closes the pooled websocket connections, also after a timed-out close. A reasoning item replays with its provider data. The model sees the session history from the newest compaction summary on.
- **Model API backends** (`harness`, `harnesstest`) — a `type: openai-compat` provider, such as Bifrost, and the `anthropic` provider with no type run `Runtime` turns on the chat-completions and Anthropic Messages wires, through the one backend that also runs `type: openai`. `Options.ModelTransport` supplies the HTTP transport of each, and may supply the credentials, so the key variable may be unset. Each request sends a baseline response cap of 8192 tokens, which a reasoning request can raise. A response with no text and no tool call fails as `modelapi: the response has no output`. `harnesstest.Request.MaxTokens` reports the cap that a request sends, on each wire.
- **Embedder tools** (`harness`, `protocol`) — `Options.Tools` takes `Tool` values that the model can call. After a model call that asks for tools, the turn runs each call in order, records its result, and calls the model again, until a call asks for no tool. A tool error, or a call to a tool that the session does not allow, is an error result that the model sees. `CreateSession.AllowedTools` restricts the tools that the model sees and may call; nil allows every tool. An interrupt stops a running tool, and the call gets an interrupted result. A handoff lets a running tool finish and starts no new tool. `ToolCall.ID` is the model's call ID.
- **Claude Code backend** (`harness`) — a `type: claude-code-cli` provider runs each turn of a `Runtime` session as one `--resume` run of the Claude Code CLI over stream-json. The CLI runs its own tools and compacts its own context. Its messages are recorded as items, its compaction as `compaction.applied` with `by_backend`, and its usage and context window as turn usage and `context.measured`. The `result` frame of each turn gives the context gauge, which is the prompt size of the newest call of the main thread, or the usage of the frame when no call carried usage, and its `total_cost_usd`, which adds to `session_cost_usd` of `subscription_usage`. A turn whose CLI fails, with an error `result` frame or with no result, runs the CLI once, with no `prompt_retries` run, and its error keeps its retryable class, so a goal pauses on it. A `result` frame sets the reading also when it carries no prompt tokens, so a compaction that the CLI ran reads 0. A `steer` input reaches the CLI on stdin while a tool runs. `Session.Interrupt` and a handoff send SIGINT to the process group of the CLI. Every item that the CLI wrote before it exits is recorded, and a tool call with no result gets an interrupted result, or a cut-off result before `turn.suspended` on a handoff. A stopped turn whose CLI still writes a success result completes. A stopped turn whose CLI exits with no result ends with the stop, never as a retryable failure. A turn that resumes after a handoff sends a fixed continuation message instead of its input when the resumed CLI session already holds that input. The message says that the previous turn was interrupted, and names no cause. The external session ID is saved in `backend.state` records, and with `session_mirror: true` the state also holds the transcript that `--session-mirror` reports, so a session opened on another runtime resumes it. A mirrored session with no saved transcript starts a new CLI session. Embedder tools reach the CLI through a loopback MCP server named `harness` that each turn serves while it runs, given to the CLI with `--mcp-config` and allowed with `--allowedTools mcp__harness`. A call runs `Tool.Run` with the CLI tool use ID as `ToolCall.ID`, and a call with no tool use ID is an error result. Items record the call by the embedder tool name. A call that an interrupt or a handoff stops gets no reply, so it gets an interrupted or cut-off result. `CreateSession.AllowedTools` names built-in tools of the CLI and embedder tools. The built-in names map to `--tools` with `--strict-mcp-config`, and the MCP server offers only the allowed embedder tools and the allowed tools of `Config.MCPServers`. An unrestricted session gives each server of `Config.MCPServers` to the CLI in the same `--mcp-config` file, by its config name, as the engine does: a stdio server as `command`, `args`, and `env`, an HTTP server as `type: http`, `url`, and `headers`. The CLI connects them itself, the runtime does not, and `--strict-mcp-config` hides every other MCP config of the CLI. Any other name fails `Create` with `ErrInvalidRequest`, and so does an embedder tool with the name of a built-in tool of the CLI. An init frame that shows another tool fails the turn. The runtime records a tool call when its frame arrives, so a running tool shows in `View.Messages` and the event stream before its result. The parallel calls of one response are separate items in wire order, where the engine grouped them in one journal message.
- **Live frames** (`harness`, `protocol`) — `Session.Events` also yields the ephemeral frames of a running turn to a live reader: `item.started` and `item.delta` (`protocol.ItemFrame`) for the text and reasoning deltas of the Codex backend, and `status` (`protocol.StatusFrame`) while a turn waits to retry. The Claude Code backend sends each finished text or reasoning block as one delta. An item that a failed attempt started never completes, and the next attempt starts a new item. The store never holds them. Each frame has `Ephemeral` set and the last durable seq, and its `item_id` is the `item_id` of the `item.completed` record that ends the item. A reader that resumes after a seq gets the durable events of the gap, then live frames. A slow reader can miss any frame, never a durable event, so the deltas of an item can have holes; its `item.completed` holds the whole item. `View.Events` yields durable events only.
- **Compaction status frames** (`harness`, `protocol`) — a compaction that runs between turns, automatic or from `Compact`, sends an ephemeral `status` frame with `compacting` when it starts, then `idle` when the summary is appended or `compaction_failed` when it is not, as the engine did. The frames carry the compaction ID in `turn_id`, and the session stays `idle` while the compaction runs. A Claude Code turn sends `compacting` when the CLI reports that it compacts, then `running` when the summary is appended, or `compaction_failed` when the CLI reports a failed compact result or ends the turn with the compaction unsettled.
- **Model list** (`harness`, `internal/modelmeta`, `protocol`) — `Runtime.Models` returns the models that the configured providers serve, sorted by ID, each with its provider and context window (0 when the backend reports it during a turn, as Claude Code does). It does no I/O. `modelmeta.Models` lists the models of a provider: the ChatGPT subscription models for `codex` and the CLI aliases for `claude-code`. Other providers list no models.
- **Session settings** (`harness`, `protocol`) — `Session.Update` takes a `protocol.SettingsPatch` that changes the model, the effort, or the service tier, appends `settings.changed` for the values that differ, and returns the view. A running turn uses the new settings from its next model call. A model that no configured provider serves, or that `modelmeta` does not know, fails with `ErrModelUnavailable`, and an unknown effort with `ErrInvalidRequest`. A session can move between Responses providers, such as `codex` and `openai`, and the next provider gets the whole history. A turn that a handoff resumes uses the settings at its resume. A backend that has no service tier ignores it.
- **HTTP API** (`harness`, `protocol`) — `Runtime.Handler` serves the session API over HTTP: `POST /sessions`, `GET /sessions?after=&limit=`, `GET` and `PATCH /sessions/{id}`, `POST /sessions/{id}/inputs`, `POST /sessions/{id}/interrupt`, `GET /sessions/{id}/events`, `GET /models`, and `GET /health`. A route that names a session opens it through `Runtime.Open`. A new input answers 201 and a repeat of its ID answers 200 with the original receipt; `Session.Admit` is `Submit` with that verdict. An `Accept` header selects SSE only when it lists `text/event-stream` with a quality above 0. `GET /sessions/{id}/events?after=&limit=` returns a `protocol.EventPage` of durable events; with `Accept: text/event-stream` it streams the durable events after `after`, or after `Last-Event-ID` when it is set, then the live ones with the ephemeral frames between them. A durable frame carries its seq as the SSE id, and an ephemeral frame has no id. An error is a `protocol.ErrorBody` with a code from the `protocol.Code` constants, mapped from the sentinel errors; an unmapped error is `internal` with a fixed message, and a path or method that no route serves answers 404 or 405 with `invalid_request`. A body above 8 MiB fails with `payload_too_large`. `GET /sessions/{id}/inputs` returns the queued input IDs without opening the session, and `DELETE /sessions/{id}/inputs/{input}` opens it, withdraws the input when it is still queued, and answers 204 either way. The handler has no authentication; the embedder wraps it.
- **Runtime compaction** (`harness`, `protocol`) — `Session.Compact` and `POST /sessions/{id}/compact` fold the turns before the newest `compaction_keep_turns` (default 2) into a summary that the session model writes with the compaction prompt of the engine, and append `compaction.applied` with `by_backend: false`. The next model call reads the summary first. A session with too few turns appends nothing. A Claude Code session runs `/compact` as a turn of the CLI, which logs `compaction.applied` with `by_backend: true`. `Session.Compact` and the route take `keep_turns`, which replaces `compaction_keep_turns` for one call; below 1, or for a Claude Code session, it is `invalid_request`. `Compact` returns when the compaction ends, and fails with `ErrSessionBusy` (`session_busy`, 409) while a turn runs or inputs wait. Before a queued input starts a turn, a session whose newest `context.measured` reading is at or above `compaction_threshold` (default 0.8) of its window compacts first. A failed summary appends nothing, and the turn starts on the full history. A handoff stops a running compaction, and the next owner runs the input that waited for it. `Open` starts the next queued input when no turn is open. The Codex backend records the prompt size of each model call that reports prompt tokens, and the model window, as `context.measured`. A `compaction_threshold` or `compaction_keep_turns` at or below 0 is the default.
- **System prompt** (`harness`) — `Options.WorkDir` names the directory of a coding agent. Each session reads its system prompt once, when it is created or opened: the base prompt, `append_system_prompt`, the `AGENTS.md` chain from the git root down to `WorkDir` cut at `instructions_max_bytes` (default 64 KiB; a negative value keeps the whole file) with a marker, and the skill list. A file that cannot be used is skipped with a WARN log line. With no `WorkDir`, the prompt is `append_system_prompt` alone and no file is read. The log never holds the prompt. A Claude Code session gets `append_system_prompt` as one `--append-system-prompt` value, and the CLI runs in `WorkDir`.
- **Processes** (`harness`) — with `Options.WorkDir`, the runtime runs `Config.Processes` through the `process` tool: `start`, `stop`, `restart`, `status`, `logs`, `list`, `declare`, and `undeclare`. Each turn sends a status line inside `<harness-engine-context>` tags after the system prompt that names each started process, its state, its ports, the instant of its last change, and its log path. `Runtime.Close` stops every process, also when its ctx ends first. When its ctx ends first, `Close` cancels the turns and waits for them to end before it returns, as the engine `Drain` does. With no `WorkDir`, no process runs and the model sees no `process` tool. `declare` runs any argv, so a `WorkDir` grants command execution.
- **Box routes** (`harness`, `protocol`) — `Runtime.Handler` serves the process manager of the `WorkDir`: `GET /processes`, `POST /processes/{name}/start`, `stop`, and `restart`, and `GET /processes/{name}/logs?tail=`. An unknown process is `process_not_found` (404). After `Runtime.Close` starts, a `start`, `stop`, or `restart` fails with `draining` (503), and `Close` waits for one that runs. With a `WorkDir`, `GET /workspace/changes?scope=&dir=` returns the git diff of the work tree as a `protocol.WorkspaceChanges`, by the rules of `GET /git/changes`, with the errors `not_a_git_repo`, `no_base`, and `too_many_changes` (409).
- **Slash commands** (`harness`, `protocol`) — `Session.Admit` resolves a typed input (`source: typed`) as a slash command by the rules of `harness serve`. A control command records `command.recorded` with `accepted`, runs through the Go API after `Admit` returns, and records `succeeded`, `failed`, `refused`, or `interrupted`; a panic of the operation records `failed`. `/compact [keep_turns]` passes `keep_turns`, and its result is the `from_seq` and `to_seq` of the compaction, or `by_backend: true`; bad arguments fail at once, and a frontend command is `unsupported`. A command that needs an idle session is `refused` while a turn runs. The receipt carries the status in `command`, and a repeat of the input ID returns it. `Open` records `interrupted` for a command that an earlier owner never finished. An unknown name is text, `//x` is `/x`, and a prompt command under `commands_dirs` is its expanded text with source `command`. `Runtime.Commands` and `GET /commands` return the menu with `serve_support`.
- **MCP tools** (`harness`) — a `Runtime` session gets the tools of `Config.MCPServers` as `mcp__<server>__<tool>`. The first model call of a turn that the runtime serves the MCP tools for connects every server once for each runtime; an unrestricted Claude Code turn connects none, because the CLI does. A server that fails stays down until the model calls `mcp(action="connect")`. With `mcp_tool_loading` `lazy`, or `auto` over `mcp_tool_loading_threshold` (default 20) tools, or a server `tool_loading` of `lazy`, the system prompt lists the deferred tools, and the model loads one with `mcp(action="select")` or finds one with `mcp(action="search")`. A loaded tool is callable on the next request of the turn, and a call of a deferred tool runs it. The history decides which tools are loaded, so a replay loads the same tools. The instructions of the servers that the first connect reached join the system prompt in `<mcp_instructions>`. A server that serves resources adds `list_mcp_resources` and `read_mcp_resource`. An image, audio item, or binary resource of a result is a blob for the model, and an error that is not the server's own RPC error never names the endpoint URL or a response body. `Runtime.Close` closes every connection. With `mcp_servers`, an embedder tool with an MCP tool name fails `New`. The base prompt of a `Runtime` session says that the harness appends the process status to the system prompt.
- **Model call recovery** (`harness`) — a `Runtime` session recovers from a failed model call by its class. A context overflow compacts the session while the turn runs and calls the model again; when no turn can fold, the turn fails. A provider usage limit, such as a spent quota, ends the turn `failed` with cause `provider_exhausted`. A model call that reports no wire activity for `stream_idle_timeout_s` (default 300; a negative value turns it off) stops and runs again as a retryable error; tool arguments that still stream count as activity. A response cut off at `max_tokens` runs none of its tool calls, which get an error result, and the next call asks the model to continue, up to `max_tokens_continuations` times in the turn; past that the turn fails, and 0 or less ends the turn at the cut. The continuation message is not logged. Any other error fails the turn. A Claude Code session has no stall limit.
- **Goals** (`harness`, `protocol`) — `Session.SetGoal` and `Session.ClearGoal`, and `PUT` and `DELETE /sessions/{id}/goal`, run a `Runtime` session goal as Claude Code `/goal` does. On a session with no running turn and no queued input, the condition is the input of the first turn, with `source: goal`; otherwise the next turn that ends is the first one judged. `SetGoal` needs `goal_evaluator_model`. After each turn that completes or is interrupted while the goal stays active, that model judges the history; a reply that starts with markdown marks still counts,. The verdict: `met` achieves the goal, `impossible` fails it, and `not_met` admits its guidance as the next input until `max_turns` (0 is unlimited) exhausts the goal. A retryable error or a usage limit pauses the goal, which runs again after a backoff from 30 s to 30 min, or at the next input; any other error fails it. A verdict, a pause, or a failure withdraws the queued goal input. `ClearGoal` stops a goal turn with cause `goal_cleared`. An interrupt while the goal is active ends the goal, during a goal turn, a judgment, or a compaction: the goal becomes `cleared` with reason `interrupted`, its queued input is withdrawn, and no goal turn starts. The engine left the goal active after an abort, and the runtime has no parked goal. A goal has one retry timer, and any change of the goal stops it. `ClearGoal` starts an input that a paused goal left queued. `Open` judges the last turn of an active goal and keeps the retry time of a paused goal. `protocol.Session.Goal` reports the condition, state, judged turns, reason, and retry time. There is no deferred goal.
- **Plugins** (`harness`) — a `Runtime` session gets the tools and hooks of `Config.Plugins`. The first `Create` or `Open` of a runtime reads the manifest of each plugin with one probe, bounded at 30 s. A probe that fails, a manifest of another name, or a plugin tool with the name of another tool or of a built-in tool of the model backend fails that call, and the next call tries again; a call after `Close` returns `ErrDraining`. A plugin process starts on its first hook or tool call. `tool.execute.before` can rewrite or deny each tool call, and `tool.execute.after` can rewrite its result, also for a call that a backend that owns the loop makes. The `system.transform` segments of each model call, which get the model of the call, follow the MCP segment. The `event` hook gets `session.status` and `session.error` from the appended turn records, `tool.execute.start` and `tool.execute.end` around each call that runs, and `file.edited`, with an absolute path, after a `write_file` or `edit_file` call that succeeds. `client/session.messages` reads the session from the store, with each attachment as a `blob` part and its bytes. The runtime does not dispatch `chat.params`, `chat.message`, or `shell.env`, and fails `client/mcp.call`. `Runtime.Close` stops every plugin process.
- **Config rules** (`config`) — `Config.Validate` is the one rule set for a hand-built or loaded `Config`, and never changes it. `Defaults` returns the built-in value of every defaulted key. `Config.ApplyEnv` sets each top-level string, number, or bool key from a non-empty `HARNESS_<KEY>` variable, and a parse error names the variable but not the value. `ProcessSpec.Validate` is the process entry rule that `process.Declare` also uses. The package imports only the standard library.
- **Built-in tools** (`harness`) — with `Options.WorkDir`, each `Runtime` session of the harness loop gets the built-in tools of the engine, with their behavior, limits, and text: `read_file`, `write_file`, `edit_file`, `glob`, `grep`, `ls`, `bash`, `read_tool_result`, and `session_info`. An embedder or plugin tool with one of these names fails. Each session has its own `write_file` guard. `session_info` takes no argument and reports the session, the system prompt and the tools that its newest model call sent, the instructions files and skills that the session read when it started, and the plugin inventory to the model. `read_file`, `edit_file`, and the `write_file` guard fail on a file above 20 MiB. A tool result above 16384 bytes has its secrets masked, goes to a blob, and the history holds a preview with a `trh_N` handle that `read_tool_result` reads back; a `tool_result.retained` record names the blob, and `Sync` carries the blob. A result that would take the session above 4 MiB of retained results keeps only its preview. The runtime does not read `tool_result_inline_bytes` or `tool_result_retained_bytes`. Retention runs after the plugin hooks. Each compaction summary ends with an index of the newest retained results. `read_file` reads an image as a summary line and the image. A backend that owns the loop, such as Claude Code, gets none of these tools. With no `WorkDir`, a session has none of them.
- **Documentation** — package docs on pkg.go.dev and runnable programs in [`examples/`](examples).
- **Children** (`harness`, `config`) — with a `WorkDir`, each `Runtime` session has a `task` tool, `{agent, prompt}`, that starts a child session in the background and returns its ID at once. The child is a session with `parent_id`; its first turn runs the prompt. When a turn of the child ends, the parent records `child.settled` and gets a report input with `source: child`: the outcome (`done`, `failed`, or `canceled`), the error, and the last assistant text of the child. A parent that opens after a crash settles each child that ended and opens each child that did not. Agent profiles load from `<workdir>/.agents/*.md` in the agent format of Claude Code (`name`, `description`, `tools`, `model`, and a prompt body) beside the built-in `general-purpose`, `explore`, and `plan`, and set the allowed tools, model, and prompt of the child. `explore` and `plan` allow only the read-only file tools. `max_task_depth` (default 3) and `max_concurrent_tasks` (default 20) bound each session tree.
- **Goal tool** (`harness`) — with `goal_evaluator_model`, each `Runtime` session that is not a child has the `goal` tool of the engine: `status` reports whether a goal is active and its condition, `set` starts a goal with no turn limit and fails while one is active; the condition runs as a turn of its own after the current turn, and the goal judges the turns after it, and `adjust` replaces the condition of the active goal and keeps its turn count and `max_turns`. A turn of a backend that owns its loop, such as Claude Code, gets no `goal` tool. There is no `clear` action. `goal.set` gains `turns`.
- **Task actions and tree interrupt** (`harness`, `config`, `protocol`) — the `task` tool takes the engine actions `cancel`, `status`, `send`, and `log` on a `session_id` that the caller spawned, directly or transitively; `action` defaults to `spawn`. `send` runs a settled child again, and the child reports the new turn. `cancel` withdraws the queued inputs of the target and its descendants and stops their turns. `protocol.Interrupt.Tree` and `POST /sessions/{id}/interrupt {"tree": true}` also withdraw the queued inputs and stop the turn of each descendant, which settles `canceled` with no report input. `max_tree_tokens` (`HARNESS_MAX_TREE_TOKENS`; default 0, no limit) stops a spawn once a session tree has used that many tokens.
- **Steering for every backend** (`harness`) — a `steer` input, and a `send` of the `task` tool, joins a running `Runtime` turn of a model API backend (Codex, Anthropic, Bifrost) at the next item boundary: after the tool results of a response, before the next model call. The model reads the inputs that join together as one `OPERATOR MESSAGES (address these, then continue the task):` message with a numbered list, as the engine writes its injected prompts. A response that ends the turn at its `max_tokens` stop takes no steer input, so that input runs as the next turn. A `queue` input still waits for the next turn.
- **Session telemetry** (`harness`, `protocol`) — `protocol.Session` has `context` (`tokens`, `window`), `last_turn` (`turn_id`, `stop_reason`, `error`), `compaction_count`, and `subscription_usage`, the newest subscription limit snapshot of the Codex and Claude Code lanes (`provider`, `plan`, `windows`, `overage`, `captured_at`). `usage` sums every model call of the session, the summary calls included and the goal evaluator calls not, as in the engine. Each model call that measures anything records one `context.measured` record with its `usage`, and a summary call adds `usage` to its `compaction.applied` record, so a handoff, a crash, and a restart keep the usage. `turn.ended` has no `usage`. The actor masks and bounds the error text of a failed turn and of a goal stop (`turn.ended` error, `goal.changed` reason) as the engine did: recognized credential shapes redacted (best effort: a free-form text can hold a shape that the fixed patterns miss), and a text longer than 256 runes keeps its first 256 runes and ends with `...[truncated]`.
- **Compaction result** (`harness`, `protocol`) — `Session.Compact` returns a `protocol.Compacted` with `from_seq`, `to_seq`, `by_backend`, and `folded`, and `POST /sessions/{id}/compact` answers `200` with it. `folded` is false when the session has too few turns.
- **Engine banner** (`harness`) — with `Options.Version`, each model call of a harness-loop turn sends the status line `[engine: harness <version> · session_sync=<mode> · engine started <time>]` as engine context, as `harness serve` does. The first request of a session pins it after the newest message of the history, and each later request keeps it there until a compaction applies, which moves it to the end of the history that it leaves, so a kept tool call stays paired with its result. A turn of a backend that owns its loop, such as Claude Code, gets none. Empty: no banner.
- **Crash marker** (`harness`) — `Open` ends a crashed turn with the assistant item `[harness: this turn was interrupted by a process restart and could not complete]` before `turn.ended`, as the engine did, so the next user message no longer joins the crashed one on the wire.
- **MCP connect reasons** (`harness`) — `mcp(action="connect")` names the class of a failed connect, as the engine did: `initialize timed out`, `initialize cancelled`, `connection refused`, `connection failed`, or `initialize failed`. It never names the endpoint URL or a response body.
- **MCP retry, down notice, and status** (`harness`) — an MCP server that fails its first connect retries in the background, as the engine did: the first wait is about 1 s, it doubles for each failure, and half of it is random. After 3 failed retries the server is parked until `mcp(action="connect")` connects it. While a server is down, the model reads `[mcp: unavailable — <server> (<reason>; retrying). Tools from these servers are temporarily absent and may return later in this session.]`, and a parked server reads `use the mcp tool action "connect" to retry`. The notice is a message of the conversation, in `<harness-engine-context>` tags, pinned at the first model call that sees a new text and kept at that place by each later call until a compaction moves it to the end of the history, so the system prompt never changes and a kept tool call stays paired with its result. The tools of a server that connects appear at the next model call, and the last server to connect adds `[mcp: every configured server is connected again.]` the same way. `mcp(action="status")` reports `{name, connected, attempts, parked, reason}` for every configured server.
- **MCP prompt bounds and compaction guards** (`harness`) — the MCP prompt segment is bounded as the engine bounded it: the instructions of one server are cut at 4000 runes with `… [truncated]`, its tool names stop before 2048 bytes with ` names truncated at byte budget`, and the deferred catalog lists the first 200 tools and ends with `... and N more tools; use mcp(action="search", query="...") to find them`. Automatic compaction estimates the context from the history (1 token for each 4 bytes, 1600 for each image) when a turn has ended and the newest turn recorded no reading, and after an automatic compaction applies, or its summary comes back empty, it waits until the context falls below the threshold once before it runs again; a model change that moves the window ends the wait.
- **Plugin inventory** (`harness`, `protocol`) — `protocol.Session.Plugins` lists each configured plugin of the runtime with its name, its state (`not-spawned`, `running`, or `errored`), its tool names, and its hook names, as the `harness serve` session view did. `Session.View` and `Runtime.List` read the state live; a session log does not hold it.
- **Model tool** (`harness`) — with a `WorkDir`, each session has the `model` tool, as the engine had it: `status`, `list`, and `set`, with a `billing` of `subscription` or `api` for each provider. The providers are the registry of the engine: the native `anthropic` and `openai`, the default `openrouter`, and each configured entry, and a `set` to a native provider builds its client as the engine did. `set` calls `Session.Update`. A backend that owns its loop gets `list` alone. `model_tool: false` turns it off, and `New` reads the key again.
- **Model and effort of `task spawn`** (`harness`) — a spawn takes `model` (a `provider/model` ref that a provider of the registry serves) and `effort`, and checks both before it starts the child. A child with no `effort` has the provider default, as the engine did, and no longer takes the effort of its parent.
- **Subagent frames** (`harness`) — a Claude Code session runs the CLI with `--forward-subagent-text`, as the engine did, and records the text, the tool calls, and the tool results of a subagent as items. `eventlog.Message.ParentCallID` (`parent_call_id` in the log) names the tool call that started the subagent, and is empty for an item of the session itself, so a client can nest the subagent work under its call. The model never reads it, and the wire order of the main thread and a subagent thread stays.
- **History bridge** (`harness`) — a session can move between Claude Code and a model API in either direction. A turn of a backend that owns its loop, such as Claude Code, gets the tool `get_conversation_history`, which reads the live history of the session page by page (`offset`, `limit`) as the engine tool did, and which no allow list hides. When the history holds a message that another provider recorded after the last turn of this one, the turn adds one line to `--append-system-prompt` that tells the CLI to call that tool before it answers. The next turn of the same provider adds none. A turn belongs to the provider of its model at its start, so a model change in the middle of a turn loses no history, and a turn that recorded no item, such as one whose CLI never started, shows its backend nothing. `eventlog.State.Foreign` derives that from the log; nothing is stored. A turn that is running moves to a model of another kind of backend at its next turn, not at its next model call.
- **Questions** (`harness`, `protocol`) — with `Options.AskUserQuestion`, a Claude Code turn may ask the user an `AskUserQuestion` question, as `harness serve -ask-user-question` did. The CLI runs with `--permission-prompt-tool stdio` and a hook that defers the call, `EnterPlanMode` and `ExitPlanMode` are off, and the turn ends `awaiting_input` after a `request.opened` record (kind `question`, the call ID as the request ID, and the tool input as the payload). The session reads `waiting`. `Session.Resolve` and `POST /sessions/{id}/requests/{request}` take `{answer}` or `{dismiss: true}`; a question takes a map of each question to the chosen label or free text. An answer appends `request.resolved` and runs a turn with no input, which resumes the CLI and answers the call over the control channel. The call stays open until that turn records the result of the CLI for it; a turn that records none gives the call a cut-off result. A question takes only a non-empty map of text, and any other answer fails with `ErrInvalidRequest`. A dismissal runs no turn. An input that is admitted, or queued before the question, dismisses it first: the next run of the backend then denies the parked call in a run of its own, with an interrupt, before the prompt. A request that is not open fails with `ErrRequestNotPending` (`request_not_pending`, 409). A child session and a session with an active goal never ask. A request that nothing resolves keeps the session `waiting`; a crash dismisses it.
- **Tool-result images** (`harness`, `protocol`) — a tool result can carry blobs: `protocol.ToolResult` has `Blobs`, each a media type and its bytes. `read_file` of an image and an MCP result with image, audio, or resource-blob content return them, as the engine did, so the model sees the image. A turn stores each blob with `Store.PutBlob` under `toolblob-<sha256>` before it appends the `item.completed` whose `tool_result` part holds `blobs` (`media_type`, `blob_key`, `bytes`). `Sync` carries the blobs of that record, a replay or `Open` sends the same image, retention counts the text only, and `GET /sessions/{id}/blobs/{key}` still serves attachments only. When the Store lacks the bytes of a blob, the model API backend logs a WARN and sends the text of the result without the image, so one lost blob does not fail every later turn.
- **Prompt attachments** (`harness`, `protocol`) — an input can hold a blob part, `{type: "blob", media_type, data}`, as the engine took: a png, jpeg, gif, webp, or pdf of at most 20 MiB whose bytes are the type that it claims. The runtime stores the bytes with `Store.PutBlob`, and `input.admitted` holds a blob part with `media_type`, `blob_key`, and `bytes`. `Sync` carries the blob in the batch of its record. `modelapi` sends it to the model, and `claudecode` sends an `image` or `document` content block. The inputs route takes a body of 32 MiB, and every other route 8 MiB.
- **Agent profile dirs** (`harness`) — `agent_defs_dirs` selects the dirs of the agent profiles of a `Runtime`. A relative path joins `WorkDir`, and the default is `<WorkDir>/.agents`.
- **Engine parity of the runtime** (`harness`, `protocol`) — `Runtime.List` and `GET /sessions` list in creation order, and `after` is the ID of the last session of the page before it; an `after` that names no session fails with `invalid_request`. `POST /sessions/{id}/requests/{request}` replies `202 {seq, status}` for an answer, and `Session.Resolve` returns a `protocol.Resolved`. The `[continuation: …]` message of a max_tokens turn is in `<harness-engine-context>` tags. A settings change to a model of another kind of backend fails the running turn at its next model call. A name that two agent definition files repeat, in one directory or across `agent_defs_dirs`, fails the spawn and names both files.
- **Model call log lines** (`harness`, `cmd/harness`) — a `Runtime` writes one `turn_metrics` line through `slog` for each completed model call, and one `startup_prewarm` line for each state of a Codex warm-up, with the keys of the engine. `turn_metrics` has `session_id`, `model`, `ttft_ms`, `stream_ms`, `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens`, `system_len`, `tools_count`, and `retry`; `request_mode` and its item counts, `service_tier`, `effort`, and the `chain_refusal` keys appear only when they apply. `startup_prewarm` has `session_id`, `status` (`started`, `ready`, `consumed`, `stale`, `failed`, `timed_out`, or `cancelled`), `duration_ms`, and `age_ms`. `harness run` makes its JSON logger the default logger, so these lines are JSON on stderr there as on `harness serve`.

### Changed

- **Small engine points** (`internal/session`, `internal/prompt`, `internal/skill`) — the transcript that the goal evaluator reads shows a reasoning part as `[reasoning] <text>` and a blob part as `[blob <media type>]`, ends a part over 4096 bytes with `…[truncated]`, and opens with the engine omission notice when it leaves out earlier messages. An agent profile with an unknown key and another error fails the load with the other error, as the engine did, and a profile with an unknown key alone is still skipped. A prompt command with an unknown key and another error still lists the unknown key as its reason. An interrupt of the first turn while it waits for the Codex warm-up cancels the warm-up, which logs `startup_prewarm` with status `cancelled`.
- **Engine text of children, goals, and agent profiles** (`harness`, `internal/session`, `internal/tree`, `internal/prompt`, `internal/backend/claudecode`) — a child report to an idle parent starts its turn with the trigger sentence of the engine and the pinned `[tasks: …]` segment, and the history holds the sentence alone. The `task` tool answers a spawn with the engine note, refuses an unknown agent as `unknown agent "x" (available: …)`, and refuses a spawn past `max_concurrent_tasks` or `max_tree_tokens` with `engine: tree concurrency limit reached` and `engine: task tree token budget exceeded`. A session at `max_task_depth` has no `task` tool. The goal evaluator reads a tool call as `[tool call <name>] <arguments>` and a result as `[tool result] <text>`, the `goal` tool refuses with the engine wording, and an `adjust` while the condition of a `set` still waits replaces it, so the turn of its own runs the adjusted condition. An agent profile file with no `name` or no `description` fails the load and the error names the file; a file with an unknown key is still skipped. A Claude Code `result` with no turns and no text ends the turn when the run already recorded an assistant item, with the usage of that result, as the engine ended it.
- **Cancel reports its canceled descendants** (`internal/tree`, `internal/session`) — `cancel` of the `task` tool settles each canceled descendant of the target in its own parent with no report input, and reports it to the nearest ancestor of the target that is not terminal, as the engine did: the parent of the target when that parent works, else the session that called `cancel`. The report of the target goes to that ancestor too, chosen when the report is delivered, so a target whose parent is done reports to the session that called `cancel`. A parent that opens while that report is delivered leaves the target to that delivery, so the report reaches one session. The `turn.ended` of a turn that `cancel` stops carries `task_cancel` (cause stays `stopped`), so after a crash the parent that opens routes the report again to the nearest live ancestor, relays it when that is not the parent, and settles with no report input. A relay is kept once for each child and turn, so a crash between the relay and the settle does not report twice. A `goal` `adjust` takes effect on the turn that calls it: the turn is judged on the new condition, with no stale verdict and no spent turn.
- **Engine parity of agent profiles and the evaluator budget** (`internal/skill`, `internal/session`) — an agent profile with an unknown key and a list or a block of text under it fails the load, as the engine did, where the runtime skipped the file; an unknown key with an inline value, a mapping, or block text that holds a colon still skips it. The goal evaluator reads a transcript of half the window of the evaluator model less 2048 tokens, at 4 bytes for each token, where it read a fixed 128 KiB; a model whose window the backend only estimates is sized with a 16000-token window in that formula, as in the engine.
- **Plugin shell.env** (`internal/tool/builtin`, `internal/tool/pluginsrc`) — a plugin that subscribes to `shell.env` adds environment variables to each `bash` command, as the engine did.
- **Plugin chat.params** (`internal/turn`, `internal/tool/pluginsrc`) — a plugin that subscribes to `chat.params` runs before each model call and may set the model, `max_tokens`, `temperature`, and `top_p` of that call, as the old engine did. An empty model keeps the session model.
- **Plugin manifest cache** (`internal/tool/pluginsrc`, `config`, `cmd/harness`) — the first `Create` or `Open` reads the manifest of a plugin from the cache file when the plugin has not changed (the executable and each script argument, by size and mtime, then by content hash), as the engine did, so it no longer waits for a probe of each plugin. The cache file is the config key `plugin_cache` (`HARNESS_PLUGIN_CACHE`), which only the user config sets. `harness serve`, `run`, and `plugin probe` default it to `plugin_cache.json` beside the user config. `harness plugin probe` probes every plugin again and refreshes the file. The Go API has no default and probes at each start.
- **Oversize instructions** (`internal/prompt`, `config`) — an `AGENTS.md` over `instructions_max_bytes` keeps the sections that fit whole and gets an outline of the rest, each line with the `read_file` range that reads the section, as the engine did. A first section over the cap, or a file with fewer than two sections, gets the truncation marker. `instructions_mode: "full"` or `HARNESS_INSTRUCTIONS_MODE=full` keeps the head and the marker for every file. A chain over four times `instructions_max_bytes` loses its middle files, nearest the root first.
- **Read-only subagents** (`internal/prompt`) — the built-in `explore` and `plan` profiles allow `session_info` beside the read-only file tools, as the engine's allow-list had it.
- **Tool batching** (`internal/prompt`) — with a work directory, the system prompt of a session on a model API backend tells the model to put independent tool calls in one message, after the `append_system_prompt` entries and before the `AGENTS.md` chain, word for word as the engine did.
- **Parallel tool calls** (`internal/turn`, `internal/tool/builtin`) — the tool calls of one model response run at the same time, up to 8, as the engine ran them. Results reach the log in call order. `goal`, `model`, and `mcp` run alone; `read_file`, `write_file`, and `edit_file` on one path, `process` on one name, and `task` on one session run in call order. An interrupt cancels every running call. A budget of 64 MiB for each session bounds the file bytes that concurrent file calls hold, beside the 20 MiB cap of one file.
- **Adjacent assistant messages on the chat-completions wire** (`internal/provider/openaicompat`) — a run of assistant messages in the history becomes one wire message with their text joined and their `tool_calls` concatenated, as the Anthropic adapter merges a run. The tool calls of a Claude Code response, recorded as one item each, thus stay valid for a chat-completions model after a model switch.
- **Claude Code failure text** (`harness`) — a Claude Code `result` frame with subtype `error_during_execution` reports its failure in `errors` and carries no `result` text. The backend now reads `errors`, joined with `; `, when `result` is empty. The error of the turn names the failure, and a credential refusal in `errors` fails a goal instead of pausing it, as a refusal in `result` already did.
- **Command directory under a symlink** (`internal/command`) — a prompt command directory is refused only when the directory itself is a symlink. A symlinked ancestor, such as `/tmp` or `/var` on macOS, no longer hides the commands of a work dir.
- **Unknown model window** (`harness`, `config`, `protocol`) — a model that the built-in context-window table does not know no longer fails with `model_unavailable`. It runs with a window of 128000 tokens, logs one WARN per process and model, and sets `context.window_estimated` on the session gauge. A configured `context_window_tokens` always wins, and an overflow error does not change the window: the overflow compacts and calls the model again as before. A model that no configured provider serves still fails with `model_unavailable`. The config key `context_window_required` is deleted, and `config.Load` rejects a file that sets it as an unknown key. This is a deliberate break (Andy, 2026-10-07).
- **Engine and server deleted** (`engine`, `server`, `provider/claudecode`) — the packages `engine`, `server`, and `provider/claudecode` are gone, with `harnesstest.SinkReceiver`, `prompt.EngineBase`, `message.PartVariants`, the `typeid` package, `provider.Registry`, `skill.Discover`, `plugin.NewTestSpec`, `message.CommandRecord`, `message.ResolveOrphanToolCalls`, the `message.Origin*` constants, `message.OperatorBatchEntry`, `message.PromptSource`, and 17 `fakeclaude` modes that only the engine tests used. `harness.New` is the one Go API and `Runtime.Handler` serves the one set of routes. The `depguard` rules no longer allow `cmd` or `harnesstest` to import a provider wire.
- **Engine docs deleted** (`docs`) — `docs/engine-request-cycle.md`, `docs/goal-loop.md`, `docs/session-storage-and-queue.md`, `docs/models-and-providers.md`, and `docs/mcp-tool-loading.md` described the deleted `engine` and `server` packages, and are gone, with the Historical section of `docs/README.md`. `docs/architecture.md` and the source describe `harness.Runtime`.
- **MCP server merged into `mcp`** (`internal/mcp`) — the package `mcpserver` is gone. `mcp.Registry`, `mcp.NewRegistry`, `mcp.ToolHandler`, and `mcp.CallMeta` replace the same names in `mcpserver`.
- **Leaf packages moved to `internal/`** (`internal/message`, `internal/modelmeta`, `internal/mcp`, `internal/plugin`, `internal/skill`, `internal/command`, `internal/process`, `internal/imageclamp`, `internal/provider`) — the packages `message`, `modelmeta`, `mcp`, `plugin`, `skill`, `command`, `process`, `imageclamp`, and `provider` (with `provider/anthropic`, `provider/openai`, and `provider/openaicompat`) move under `internal/` with no change to their code, so another module can no longer import `github.com/majorcontext/harness/message` or the others. The public Go API is `harness`, `harness/config`, `harness/protocol`, `harness/storetest`, and `harness/harnesstest`. A caller reads model metadata through `Runtime.Models` and `GET /models`. `go generate ./internal/modelmeta/` rewrites the context-window tables. The `harnesstest` MCP stub (`MCPTool`, `MCPResource`) now takes its own types (`MCPResult`, `MCPContent`, `MCPError`) instead of the `mcp` package types.
- **Fresh-session cutover** (`harness`) — the repository has no old-format converter. `harness/migrate` and `cmd/harness-migrate` are deleted, and the runtime reads no engine journal, index, snapshot, or `events.jsonl`. A box keeps its workspace and starts a new session on the runtime; its old journals stay on disk unread.
- **Queued inputs** (`harness`, `protocol`) — `GET /sessions/{id}/inputs` answers each queued input, oldest first, as `protocol.QueuedInput` (`id`, `parts`, `delivery`, `source`, `source_id`, `source_label`) in place of an ID list. A text part carries its text; an attachment is `{type: blob, media_type, bytes, key}` and never its data. `Session.queued` stays the ID list.
- **`harness serve` on the runtime** (`cmd/harness`) — `harness serve` runs one `harness.Runtime` over a `DiskStore` in the session dir, and serves `Runtime.Handler` with no version prefix: the `/sessions` routes, `/models`, `/commands`, `/processes`, `/workspace/changes`, and `/health`. No old route answers. It reads the config with `config.LoadProject`, applies the `HARNESS_<KEY>` variables with `Config.ApplyEnv` and then its flags, passes the working directory as `WorkDir`, the build version for the engine banner, and `ServeURL` and `RunToken` for the plugins, and refuses the config keys that the runtime does not read (`instructions_mode`, `event_sink`, `snapshot_every_records`, `tool_result_inline_bytes`, `tool_result_retained_bytes`). HARNESS_MODEL now sets the default model through `ApplyEnv`, so boxes must check the variables that it exports before the cutover. The `HARNESS_RUN_TOKEN` bearer check, `-unauthenticated`, `HARNESS_UNAUTHENTICATED`, `--ask-user-question`, `-cors-origin`, `-no-instructions`, `-skills-dir`, `-agent-def-dir`, the config summary log line, and the GC pause watcher stay. The store of serve logs a slow store operation, a store operation that stays in flight, a created session, and a spawned task, in place of the engine hooks. After the listener is up, serve calls `Runtime.CatchUp` and opens each stored session that has work to resume (`View.Resumable`): a session with none stays closed and gets no `owner.acquired`, and a log that does not replay is skipped and logged. `SIGINT` and `SIGTERM` close the runtime and the HTTP server under one 5 s deadline, then write `serve-stop.json` in the session dir as one line, `{"stop":"handoff"|"crashed","sync":"synced"|"unsynced"}`, for `boxinit`; serve deletes the file at start, so a run that ends with no report reads as crashed and unsynced. A Sync that rejects a batch for good during the run (`Runtime.SyncStopped`) makes the report `unsynced`, and `Runtime.Close` does not fail for that session. `Runtime.List` skips a log that does not replay and logs it. Serve no longer has `-pprof`.
- **`harness run`, `sessions`, and `plugin probe` on the runtime** (`cmd/harness`, `harness`) — the three commands run on `harness.Runtime`, and `cmd/harness` imports neither `engine` nor `server`. `run` creates or opens a session (`-r`, `-c`, `-no-save` on a `MemStore`), submits the prompt as a typed input, streams the text, the tool calls, and a retry of the session and of each task child, or each event of the session and of each task child as a JSON line with `-json` that holds the `session_id`, and exits 1 for a failed turn (also under `-goal`) or command, with or without `-json`, and 3 for a goal that a verdict did not achieve. `run` ends only when its session is idle and each task child of its session has settled, so the output of a running child and the turn of its report print. `run -max-tokens` sets `Options.MaxTokens`, the output cap of each model call, as before. `sessions` lists the sessions of the store with their message counts. `plugin probe` calls the new `Runtime.ProbePlugins` and prints each plugin with its hooks; the manifest cache is gone, and the runtime probes at its first `Create` or `Open`. `run` and `sessions` write and read the event log; they cannot read an engine journal.
- **Message page** (`harness`, `protocol`) — `GET /sessions/{id}/messages?before=&limit=` and `View.Messages` answer a `protocol.MessagePage` as the engine page: `messages`, `first_seq`, `last_seq`, `total`, `has_more`, and `commands`, numbered from 1 with the compaction summary first. A limit above 1000, and a `before` or `limit` that is negative, not an integer, empty, or repeated, is `invalid_request`. The engine bootstrap form has no counterpart. The route reads a session without opening it.
- **Typed process, logs, and health bodies** (`harness`, `protocol`) — `protocol.ProcessInfo`, `ProcessStatus`, `ProcessLogs`, and `Health` type the `/processes` and `/health` bodies, and the generated contract names them. `GET /health` answers `version`, `vcs_revision`, `vcs_time`, `session_sync`, `started_at`, and `capabilities` (`delta_row_identity`), as the engine did.
- **Resumable sessions** (`harness`) — `View.Resumable` reports whether `Open` would resume a turn, a queued input, a goal, an unfinished command, or an unsettled child.
- **README and examples** — the README and the programs in `examples/` use `harness.New`, `Runtime.Create`, `Session.Submit`, and `Session.Events`.
- **Generated HTTP contract** (`protocol`) — `go generate ./protocol` writes `protocol/openapi.json` and `protocol/protocol.ts` from the Go types of `protocol` and the route table of `internal/server`, and CI fails on a diff. The hand-written `server/openapi.yaml` is deleted. The contract holds each success status of a route (a repeated input ID answers 200, an answer to a request 202), marks each request body optional, and refuses unknown fields in a request-only type.
- **Error codes in the contract** (`protocol`, `internal/server`) — `Error.code` in `protocol/openapi.json` and `protocol/protocol.ts` is an enum of the error codes of the API, generated from the status map of `internal/server`, which now holds `unauthorized` and `internal`. A test fails when the `protocol` `Code` constants, the status map, the Errors table of the spec, and the enum differ.
- **Provider tool deferral deleted** (`internal/provider`, `internal/provider/anthropic`, `internal/modelmeta`) — `provider.ToolDef.DeferLoading`, the server-side tool search tool of the Anthropic adapter, and `modelmeta.SupportsToolSearch` are gone: nothing set the field, and `internal/tool/mcpsrc` defers MCP tools for every provider, as the spec says. A gate in `internal/gates` fails a Go file that names a deleted package path, in code or in a comment.
- **Model resolution** (`config`) — `Config.ResolveModel` returns the resolved ref string and does not parse it. A caller parses it with `message.ParseModelRef`.
- **Runtime config check** (`harness`) — `harness.New` returns `ErrInvalidRequest` for an `Options.Config` that fails `Config.Validate`, so a bad provider, plugin, MCP server, or process entry fails at `New`, not at the first model call or process start.
- **Credentials from the HTTP client** (`internal/provider/anthropic`, `internal/provider/openaicompat`) — a `Client` with an `HTTPClient` and no `APIKey` sends no key header, so the client can supply the credentials, as `provider/openai` does. A `Client` with neither still fails with `no API key configured`.
- **Failed turn and the queue** (`harness`) — a `Runtime` session starts the next queued input after a failed turn, as after a completed turn, and `Open` does the same. Only a turn that ended `provider_exhausted` leaves its queued inputs waiting for the next input, live and after a restart.
- **Turn end cause** (`harness`, `protocol`) — `turn.ended` has a typed `cause` (`stopped`, `ended`, `goal_cleared`, `crashed`, `provider_exhausted`), and `error` holds only the message of a failure. `protocol.LastTurn` has `cause`. A turn that a usage limit failed keeps the provider message in `error`, with the recovery time of the provider when the message lacks it, where it held the text `provider_exhausted`. A turn that ended by its cause alone has no `error`; the report of a child and the status of a task show the cause then. Every reader branches on `cause` and never on the text of `error`.
- **Evaluator and summary calls** (`harness`) — the goal evaluator request pins effort `off` and a response cap of 256 tokens, and a summary request caps its response at 1024 tokens, as the engine does. A retry waits 1 s, doubling to 8 s. The compaction threshold and the context gauge use the window of the session model, or the window of the reading when the model reports none, so a model switch changes the window. The evaluator transcript has no trailing newline.
- **Tool names across backends** (`harness`) — one rule decides whether a session has a tool: an embedder, runtime, plugin, or MCP tool, a file tool of the `WorkDir`, or a built-in tool of its model. The `tools` list of a child profile keeps its plugin tools. A backend that owns the loop, such as Claude Code, runs no plugin `system.transform`, because it reads no system prompt of the harness. The tool hooks of every source run around each tool call, in order.
- **One read of a child profile** (`harness`) — a spawn reads the agent profile once, and the child takes its model, tools, and prompt from that read, where the child read its prompt again at its first turn.
- **Reads without ownership** (`harness`) — `GET /sessions/{id}` and the page form of `GET /sessions/{id}/events` answer from the view of a session that the `Runtime` runs, and replay the log of any other session, as `OpenView` does. They never acquire a session, append `owner.acquired`, or start a turn. The SSE stream of `GET /sessions/{id}/events` and each route that changes a session still open it. After a restart the embedder opens each session that has work to resume.
- **Reads of a running session** (`harness`) — a plugin `client/session.messages` call, `task` status and log, the tree interrupt, and the tree budget read a running session from its actor, with no replay of its log.
- **Child limits from the logs** (`harness`) — `max_concurrent_tasks` counts the unsettled children in the views of the sessions of a tree that the `Runtime` runs, with no separate ledger, so a parent that opens after a restart counts its unsettled children at once. A lock for each tree makes the count and the `child.spawned` append one step.
- **Engine-only config keys deleted** (`config`) — `Config` has no field for `instructions_mode`, `event_sink`, `snapshot_every_records`, `tool_result_inline_bytes`, or `tool_result_retained_bytes`, and `Defaults` has no entry for them. `config.EventSinkSpec` and the accessors `SnapshotEveryRecordsValue`, `ToolResultInlineBytesValue`, and `ToolResultRetainedBytesValue` are gone. `Load` rejects any of these keys as an unknown field and names it. `harness.New` no longer has a separate check for them. `config/config.go` is split into `config.go`, `specs.go`, `provider.go`, `load.go`, and `merge.go`.
- **Owner refusals** (`harness`) — a failure of `Owner.Acquire` is `ErrSessionNotOwned` that wraps the cause, so the HTTP handler answers `session_not_owned`; a call that waits for ownership when `Runtime.Close` starts fails with `ErrDraining` (`draining`, 503). `ErrBusy` is no longer exported. `Runtime.Commands` returns the `op` of each command and no route, and `GET /commands` names each route.
- **One submit** (`harness`, `protocol`) — `Session.Admit` is gone. `Session.Submit` returns `protocol.Admitted`, and `Admitted.Repeat` (not on the wire) is true when the session had admitted the input before.
- **Window before the first measurement** (`harness`, `internal/modelmeta`) — `OpenView`, `ReadHandler`, `harness sessions`, and `harness run` have no backend, so they read the context window only from the log. A session that they read reports window 0 until its first `context.measured` event, whatever its model. A live Claude Code session also reports window 0 before its first turn, because its backend reports the window during a turn. Separately, `modelmeta.ContextWindow` no longer answers for a `claude-code` ref: a model API provider that is keyed `claude-code` gets the default window of 128000, marked as an estimate, instead of window 0.
